# Full feasibility diagnosis — Mireye Universal Site Expedition

**Audit date:** 2026-08-15 UTC  
**Authority:** [`grilling_session.markdown`](./grilling_session.markdown), especially Sections 12–14, 17, and 19  
**Scope:** pre-build feasibility only; no product, cloud service, deployment, purchase, submission, or durable infrastructure was created  
**Evidence labels:** `DOCUMENTED`, `CONFIGURED`, `TESTED_OK`, `TESTED_FAILURE`, `PARTIAL`, `INFERRED`, `BLOCKED`, `UNTESTED`, `INFEASIBLE`

The status labels are deliberately stricter than “the API exists.” `TESTED_OK` means a bounded result and a reproducible method exist. `PARTIAL` means that an API call or component worked but the decision contract, authority, geometry, scale, ground truth, runtime, or policy boundary is not proven.

## 1. Executive verdict

### Verdict

**NO-GO for implementing the complete approved challenge MVP exactly as currently specified and configured. CONDITIONAL GO for a narrower, honest Site Expedition build after the blockers in Section 17 are accepted or closed.**

The core idea is technically credible and challenge-fit. The repository proves a real agent-shaped seam:

- Mireye supplies cited present-state site facts.
- Earth Engine supplies a historical witness and model disagreement.
- Deterministic code converts evidence into a reproducible decision and actionable packet.
- The San Leon/Austin replay returns `KILL`/`KEEP` in 0.04 seconds from cached, versioned inputs.

The complete MVP is not yet feasible as a truthful end-to-end claim because:

1. **Mireye has only 56 of 5,000 monthly free credits remaining.** A six-candidate, ten-field screen costs 60 credits; one full `data_center_siting` costs 106; one `site_selection` costs 363 because it includes a 300-credit parcel group. No further metered Mireye tests were justified.
2. **Route reality is a tested failure.** Routes is enabled on the Google Cloud project, but the configured key returned `403 API_KEY_SERVICE_BLOCKED`; the legacy Distance Matrix endpoint was not enabled. No route time may be shown as live.
3. **Lawful inventory is not universal.** No configured, licensed feed exists for national farm, warehouse, industrial, or data-center availability. Those Missions must use user-supplied or explicitly curated candidates and label them `USER SITE` or `POTENTIAL`, not `LISTED`.
4. **Concept Studio is unproven.** No GLB/glTF warehouse asset, placement code, buildable-envelope computation, or Concept Test exists in the repository. The Maps 3D visual stack cannot be used to derive parcel or building geometry.
5. **The Expedition orchestrator is a design, not a tested runtime.** Parallel Workstreams, cancellation, replacement, widening, evidence-graph reconciliation, and the full `STRONG FIT / REJECT / CONDITIONAL` engine have not run end to end.
6. **Model-only routing failed a controlled case.** Claude Haiku was available and consistent, but twice routed a Home flood case into `farm-history`. Skeptic Review succeeded on six synthetic defects twice; this supports a constrained reviewer, not unrestricted routing or final judgment.
7. **Several combinations remain experimental.** Dynamic World land change lacks independent validation; climate trajectory is one model/scenario path, not an ensemble; farm phenology, Routes, EIA/LODES integration, utility capacity, water rights, and entitlement remain unclosed.
8. **The current desktop prototypes are static proof surfaces.** Iteration 7 served quickly and obtained live Earth Engine map IDs and a 3D Tiles root, but it does not contain structured onboarding, candidate acquisition, Workstreams, comparison, `TODAY/FIT/FUTURE`, or a genuine live Expedition.
9. **Two existing artifacts have licensing/content-handling defects.** The FABDEM community asset used by the current height witness is CC BY-NC-SA 4.0 and is unsuitable for a commercial-capable default without separate permission. The saved Aerial HTML persists an expiring signed playback URL; only the `videoId` should be retained and resolved at runtime.

The recommended cut is therefore a six-candidate-or-smaller, user/curator-supplied Warehouse Expedition with a real flood veto, honest conditional route/availability/capacity gaps, selective Earth Engine witnesses, deterministic verdicts, and a prebuilt concept only after its independent geometry test passes. Farm, Data Center, and Home should be secondary proof recipes rather than four equal-depth products.

## 3. Tested architecture and skill graph

### Architecture that evidence supports

```text
structured controls
      -> deterministic Mission Plan compiler
      -> candidate adapter (user / curated / licensed)
      -> resolve-site
      -> cheap Mission field screen
      -> deterministic hard gates
          -> decisive reject: stop
          -> survivor: parallel question-owned Workstreams
      -> selective Earth Engine / official-source witnesses
      -> evidence graph and contradiction reconciliation
      -> deterministic comparison and provisional verdict
      -> constrained Skeptic Review
      -> final verdict + verification brief + presentation scene
```

The model may interpret controls, choose among allowed investigations, summarize evidence, and propose follow-ups. Code/config must validate Mission-to-skill eligibility, charge estimates, hard-gate semantics, evidence status, source independence, and final verdict. The model cannot invent a threshold, authorize a source, or turn a failure into a pass.

### Latency, failures, and provenance

Mireye's bundled current docs state roughly 1–3 seconds warm for `/fetch`, 2–6 seconds warm for `/ask`, up to 60 seconds cold for `/ask`, up to 5.5 seconds additional for address resolution, and up to about 84 seconds for a cold 25-location batch processed four at a time. These are documented bounds, not a measured distribution in this repository.

Observed failure classes include:

- SSURGO prime-farmland timeouts at two Farm pins;
- EPA water/sewer timeouts at Alliance and Port Houston;
- an Overture building-footprint permanent failure at San Leon;
- address/coverage absence and service failures that must remain distinct.

Every field can carry value, unit, source, URL, dataset vintage, fetch time, TTL, confidence, status, and notes; a 200 response can also contain `partial_failures`. Current harness code strips status, TTL, notes, and partial failures when constructing the record. That must be fixed before reuse.

### Address, coordinate, parcel, and ambiguity behavior

- Coordinates are WGS84 latitude/longitude and avoid address retention.
- Address fetch/geocode can be rooftop, point/interpolated, or too coarse; `parcel_grade` must gate parcel claims.
- `/lookup` returns `resolved`, `clarify`, or `no_match`; ambiguity must stop the Expedition.
- Parcel failure may degrade a good geocode without invalidating the point, but it creates a parcel Verification Gap.
- The current Mireye docs say addresses sent to Mireye are retained for audit/cache for 30 days, with opt-out by resolving client-side and sending coordinates.
- Parcel and boundary caches must key on normalized geometry hash, parcel/boundary identifier, dataset version, field manifest version, and transformation version—not a display slug or geohash alone.

### Corrections and invalid prior interpretations

1. JRC `occurrence` and monthly masks must explicitly handle no-observation pixels; `.unmask(0)` changes the meaning and must be versioned. A 60 m buffer result is not a parcel fraction.
2. Dynamic World mean class probability is not built-area percentage. The corrected modal/top-1 fraction is properly named but still lacks independent ground truth and sensitivity testing.
3. Sentinel-1 requires orbit direction, incidence angle, polarization, speckle/composite, pre/post window, and land-cover controls. “Dark means urban flood” failed.
4. IMERG half-hourly precipitation is a rate and must be multiplied by 0.5 hours when accumulated.
5. A model disagreement creates a verification action; it does not license choosing the most favorable DEM.
6. Existing water/height thresholds were created for a two-case demonstration, not calibrated regulation or a labeled outcome corpus.
7. The current `projects/sat-io/open-datasets/FABDEM` dependency inherits FABDEM V1-2's **CC BY-NC-SA 4.0** terms. The authoritative [University of Bristol record](https://data.bris.ac.uk/data/api/3/action/package_show?id=s5hqmjcdj8yo2ibzi9b4ew3sn) directs commercial use to the provider. Use USGS 3DEP as the US default and treat any second DEM as an optional separately cleared witness.

### Scale policy

- **Parcel:** only when trustworthy parcel geometry exists; validate pixel coverage and edge effects. Point/buffer metrics must not be renamed parcel metrics.
- **Buffer/surroundings:** name radius and purpose; test at least one alternate radius.
- **Watershed:** use a named HUC/basin only for hydrologic context, not parcel ownership or service capacity.
- **Regional climate:** disclose ~4–28 km support and never downscale presentation into false parcel precision.
- **Travel network:** not an Earth Engine geometry; use an authorized routing source.

### Quotas, terms, export, and cost

Official [usage quotas](https://developers.google.com/earth-engine/guides/usage) document 40 concurrent requests on each standard/high-volume endpoint and 100 requests/s per project/account, aggregation/memory limits, a 100 MiB cached aggregation-result limit, a 10 MB request-payload limit, and constrained batch concurrency. The current [noncommercial tiers](https://developers.google.com/earth-engine/guides/noncommercial_tiers) provide 150 / 1,000 / 100,000 monthly EECU-hours for Community / Contributor / Partner, require annual reverification, and degrade to restricted mode when compute is exhausted. This project's registration class, tier, and remaining EECUs were not visible in the audit and must be checked before a live demo. Commercial eligibility and current [pricing](https://cloud.google.com/earth-engine/pricing) must be confirmed before a commercial product; this hackathon configuration is not proof of production licensing.

Image exports are asynchronous and subject to pixel/format limits; direct downloads are for small results (32 MB and 10,000-pixel grid limits in the official API). Video export is RGB 8-bit MP4 with a default 1,000-frame maximum. Each underlying dataset retains its own license; Earth Engine export does not grant new redistribution rights. The MVP needs small statistics and public-source exhibits, not durable GCS/BigQuery infrastructure.

### Provider/model state

- Anthropic path: API authentication and model listing succeeded. Ten models were visible, including a current Haiku model used for bounded routing/reviewer tests. Provider billing balance was not inspectable with the standard API key, so tests were limited to a few hundred tokens.

### Routing test

A ten-case Mission-routing prompt was run twice at temperature 0 on Haiku. Each call used 415 input and 227 output tokens and completed in 2.392 s / 2.221 s. Both outputs were identical. Nine cases respected the main rules, but case A—an exact Home address with material flood history—incorrectly added `farm-history` after `flood-rewind` in both runs.

**Conclusion:** short skills are routable, but model consistency is not correctness. Mission allowlists, prerequisites, stop rules, budget quotes, and post-routing validation must be deterministic. The model should propose a plan that code can reject or repair.

### Skeptic Review test

Six synthetic cases covered shared JRC source, buffer/parcel geometry mismatch, stale listing, failed Routes treated as a pass, substation proximity treated as confirmed capacity, and a clean dated/caveated independent case. Two temperature-0 calls returned the expected six labels identically. Latencies were 1.028 s and 0.848 s; each used 275 input and 87 output tokens.

This proves only that a constrained classifier can recognize explicit defects. A production Skeptic Review must first run deterministic checks and then challenge a structured evidence graph; it must not receive hidden chain-of-thought or decide the hard verdict.

### Deterministic vs model responsibilities

| Deterministic code/config | Model-assisted judgment |
|---|---|
| Mission skill allowlist/prerequisites | Explain why an allowed Workstream could change the decision |
| quote/budget and stop conditions | Choose among equally valid optional investigations within budget |
| field/type/source manifest | Summarize evidence and draft verification questions |
| evidence status, freshness, geometry, independence | Identify a possible contradiction for deterministic validation |
| user-declared and cited hard gates | Compare preferences after required gates are supported |
| final verdict semantics and replay | Draft concise narrative from the exact trace |

### Workstream parallelism and stopping

Parallelize by question, not provider: hazards/developability, logistics/access, utilities/capacity, environmental/land history, and site identity/availability. Each Workstream needs a budget, dependency list, evidence contract, abort signal, and allowed decision effects. The controller must:

1. resolve identity once;
2. run cheap gates;
3. cancel unneeded work after a reliable veto;
4. retry only typed retryable failures with bounded backoff;
5. preserve partial evidence on timeout;
6. deepen only survivors;
7. never let one provider's failure cancel unrelated Workstreams;
8. run Skeptic Review only on finalists.

No such controller has been benchmarked; Workstream feasibility is therefore `UNTESTED` even though normal async primitives can implement it.

### Failure policy

| Failure | Required result |
|---|---|
| 401/403 credential or key restriction | Stop that source; visible `BLOCKED`; no substitute metric relabeled as equivalent |
| 402 credits exhausted | Stop further metered work; preserve completed candidates; show reset/approval action |
| 429 / retryable 5xx / typed timeout | bounded jittered retry; then `FAILED` with source/time |
| `absent` | valid semantic absence only when source defines it; not generic pass |
| permanent no-coverage / Aerial 404 | immediate documented fallback |
| stale evidence | display timestamp; refresh if authorized or downgrade authority |
| contradictory evidence | keep both; inspect geometry/time/source family; usually `CONDITIONAL` |
| required source failure | mandatory condition becomes `CONDITIONAL`, never `STRONG FIT` |

### Lawful architecture

1. Obtain authoritative/appropriately licensed parcel boundary or user-provided site plan. Do not derive it from Google imagery.

- **Prebuild:** one warehouse asset, LODs/materials, known dimensions, orientation presets, and deterministic Concept Test. This is the only credible MVP route.
- **Live:** allow bounded parameter edits (length/width/height/yard) and deterministic regeneration if performance is proven.
- **Exclude:** live generative CAD, permit-ready IFC/DXF, interior plans, machine interpretation of Google pixels, and ten presets.

### Acceptance test before implementation claim

Test the concept on one positive parcel, one known conflict, and one ambiguous/low-quality boundary.
